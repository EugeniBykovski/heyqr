# Design coverage: Claude Design → app

Reference: Claude Design artifact `5ad84e52-9181-4f2c-a6f5-04e11a8a57c9`, revision **1795163580-0e06** (77 product frames,
1.1–9.7, each rendered at 390, 834 and 1440 px). Product override: currencies **USD / EUR / PLN** (EUR in GBP's place).

How this was checked:

- **Reference renders**: every frame rendered from the handoff's own files and cropped per width.
- **App captures**: the running app (dev database, `APP_ENV=dev`) at the same widths, full page, with comparable data.
  Side-by-side evidence page: `evidence/index.html` in the session scratchpad (reference above, app below).
- **State** says how the frame's state was reached: _normal app_ (reachable through the app's own navigation and
  actions) or _fixture_ (deterministic dev data for a plan, credits, trial dates or a purchase, created by the
  scratchpad fixture script with `qa-*` ids and removed afterwards). A fixture proves how a state looks; the
  functional column says what was exercised through the app.
- **Visual**: ✅ compared side by side and matching in hierarchy, order, layout and controls; 🟡 compared, with the
  named difference; ⬜ open (captured but not yet compared in detail, or not captured in this pass).
- **Functional**: ✅ works through the app; 🟡 partial (an external integration or account is needed; see Blockers).

Totals for this pass: **18 of 77** frames pass visual acceptance, **4** are compared with known differences,
**55** are still open visually; **66** work functionally, **11** are partial.

## Blockers and missing settings

| Setting / integration                    | State here                                                                        | Blocks                                                                                               |
| ---------------------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `STRIPE_SECRET_KEY` (test mode)          | Set, but Stripe answers 401 Invalid API Key                                       | Every real checkout (3.4, 7.3), webhook confirmation (3.6, 2.11, 7.4, 9.4), receipts, billing portal |
| `STRIPE_PRICES` (per currency and offer) | Not set; USD falls back to `STRIPE_PRICE_STATIC` / `STRIPE_PRICE_DYNAMIC_MONTHLY` | Static Packs, Studio, Print Pack, every EUR and PLN offer                                            |
| `NEXT_PUBLIC_PRICE_POINTS`               | Not set; EUR has no price points (PLN uses the design's table)                    | EUR prices: shown as not set, nothing converted                                                      |
| `STRIPE_PRICE_PRINT_PACK`                | Not set                                                                           | Print Pack add-on in USD                                                                             |
| Stripe CLI webhook forwarding            | CLI installed, needs a valid key                                                  | Live webhook runs                                                                                    |
| Google OAuth consent                     | Needs a real Google account                                                       | 3.2 beyond the sign-in page                                                                          |
| ICC / CMYK conversion                    | Not available                                                                     | CMYK profiles and 100% K (shown unavailable; sRGB fully usable)                                      |

Checkout never charges a different amount than shown: it retrieves the Stripe Price and refuses a checkout whose
currency, amount or interval differ from the page's price point (`src/server/billing/catalog.ts`).
